## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-32 point 13, MULTI-TENANCY.md section 4.

AUDIENCE: the owner or office manager of a small Austrian cleaning company, 5-40 staff, who today runs paper Stundenzettel or a WhatsApp group and adds them up on the last day of the month. Not a developer. Not procurement. ON A PHONE, sent the link by another owner or in a trade group.

THE ONE PROMISE (German, and it is the whole page):
  'Ihre Reinigungskraefte halten das Handy an den Aufkleber. Die Stunden stehen fertig in der Lohnverrechnung.'
The promise is the ABSENCE OF PAPERWORK. NFC is the mechanism and mechanisms do not sell. Anything of the form 'NFC-basierte Zeiterfassungsplattform' describes us, not their Tuesday. ONE promise, not three - a page that promises time tracking AND invoicing AND materials AND analytics reads as a page that does none of them.

STRUCTURE - one scroll, six blocks:
 1. Hero: the promise, one photo of a thumb on a sticker by a door, one CTA. No signup form.
 2. In drei Schritten: tap, work, tap. Three images, three lines. The tap comes first because it is the entire product.
 3. Was Sie bekommen: Stunden, Lohnverrechnung, Kosten pro Objekt, Materialkosten. Four lines. Not a twenty-item feature grid - a feature grid is what you write when you have no promise.
 4. Daten und Betriebsrat: Server in der EU, DSGVO, Auftragsverarbeitungsvertrag, and the one that wins the meeting - KEIN GPS, KEINE LAUFENDE STANDORTVERFOLGUNG. A tag tap at a door, nothing else. Every works-council objection to phone-based time tracking is about surveillance; defuse it before it is raised, in the tenant's own words.
 5. Preis: a number. A price filters out the wrong conversations before they cost a call. If there is none yet: 'Pilotphase: kostenlos, begrenzte Plaetze.'
 6. Kontakt: a mailto: and a phone number. NO FORM. ponytail: a form needs a POST endpoint, spam handling, and storage of contact PII we would then be the controller for; mailto: is zero code and already works. Ceiling: no lead tracking, no attribution. Upgrade path: one POST route the day email volume justifies it.

HOSTING - decision-16 puts everything on one VM, and / already serves the admin dashboard (web/app/page.tsx via serveStatic). Four options were considered (MULTI-TENANCY.md 4.5); do D now, C later:
  D (now): server/routes/landing.js mirroring server/routes/wellknown.js - read the file once at boot, serve at /start with a short cache-control, plus a Host-header branch mapping <marketing host>/ to the same bytes. Then buying the domain is a config line, not a rebuild.
  Rejected: landing at / with the panel under a basePath (breaks every bookmark and the login redirect); content-negotiating / on the session cookie (a cookie-varying / is a caching and crawler trap).

PUT THE FILE IN server/public-pages/, NOT server/wellknown/. That directory is byte-compared against the live host by verify.sh and generated by ops/gen-wellknown.mjs. Adding an unrelated marketing file to the most dangerous directory in the repo is how a gate gets loosened to accommodate it.

CRAFT:
- <html lang=de>. English at /en if at all. NOT next-intl - one hand-written static file; next-intl is the panel's concern (decision-17).
- No JS, no build step, no npm dependency. Hand-written HTML with an inline <style>, following server/wellknown/t.html exactly - including its habit of writing the MEASURED contrast ratio into a CSS comment. That file is the house style; match it rather than inventing a second one.
- Open Graph tags plus one OG image. The distribution channel for this audience is WhatsApp, and a link with no preview is a link nobody taps.
- /robots.txt and /sitemap.xml, neither of which exists today. Landing is index,follow; every panel route and /t are Disallow (t.html is already noindex). Without this the thing that ranks for the company name is the admin login page.
- NO real customer names, worker names or addresses in any screenshot. Use nfc_demo (guarded by demo/check-guards.sh). This repo has already shipped a real client name into a public git blob once (TASK-37); a marketing page is a louder version of the same mistake.

ACCESSIBILITY IS A REQUIREMENT, NOT A PASS. Single column, real h1 then h2 order, CTAs are <a> not styled <div>, every image has alt text saying what it shows, >=4.5:1 body contrast with the ratio recorded in a comment, prefers-color-scheme, prefers-reduced-motion honoured - best honoured by animating nothing. Fully usable with JS disabled, which it is, because there is none.
